00 — Foundations

Arken Design System

A purpose-built design language for veterinary clinical trial data management. Every decision is grounded in GCP compliance, EDC usability, and the cognitive demands of field data capture — from research sites to barn environments.

Design principles
🔬
Clinical precisionData integrity over aesthetics. Every UI pattern is designed to reduce transcription error and support 21 CFR Part 11 audit requirements.
⚡
Role-aware densityCRC in a barn needs different information density than a Data Manager reviewing clean queries. Role context shapes layout, not just permissions.
🎯
Severity clarityThree distinct severity levels — amber / orange / red — are never merged. A protocol deviation is never visually equivalent to a welfare alert.
🔗
Audit-firstEvery change carries identity, timestamp, and reason. The system is designed to expose provenance, not hide it.

20 — Clinical · Query Lifecycle

Query Lifecycle

Three-stage progression: Raised → Responded → Resolved. Resolved is the terminal state — Arken has no separate "Closed" stage. One action per stage: CRA raises, CRC responds, DM/CRA resolves. Each stage has a single action button.

Every data edit after initial entry must carry a reason for change. The Δ symbol (monospace) marks edited values. Original value is struck through in tertiary text. New value in primary. Reason in italics.

24 — Reference · 10 Design Rules

The 10 Rules

These rules apply to every component file, every new screen, and every pattern added to the system. Non-negotiable.

1
Never hardcode hex — CSS token variables only. color: var(--red-600) not #B52626
2
No field shadow — border only. border: 1px solid var(--color-border) Never box-shadow on inputs.
3
Three severity levels — never merge amber / orange / red. Amber = query warning. Orange = raised/active. Red = critical/error.
4
text-transform: uppercase — never font-variant: small-caps. All caps labels use letter-spacing: var(--tracking-caps).
5
Roboto Mono on all data values — IDs, timestamps, measurements, counts, doses. Never Roboto for tabular data.
6
1px borders · 4px base radius — no thick borders, no overrounded components. Inputs and cards follow radius-md (4px) or radius-lg (6px) only.
7
Fields and buttons: 32px height everywhere — settings forms included. No "36px for settings" exception. font-weight: var(--weight-medium) · font-family: var(--font-sans)
8
Links: text underlined, icon NOT underlined. a { text-decoration: underline } — icon-only links use text-decoration: none
9
Every component file is self-contained — declare all tokens in :root. No file should depend on another file's styles.
10
Topbar = study pill + site dropdown. Breadcrumb = navigation path below the site level. The site name appears in the breadcrumb only when "All Sites" is selected in the top nav. When a specific site is already selected in the topbar, breadcrumb starts from the node below the site (Barn, Pen, or Subject depending on study type). See 26-data-entry.html for reference.
